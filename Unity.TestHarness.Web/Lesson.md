# Unity.TestHarness.Web

## What This Is

An ASP.NET MVC 5 reproduction of `Unity.TestHarness` (the WPF version), matching its functionality, look, and feel across all six pages. It exercises `Unity.00` through `Unity.04` end to end -- connecting, taxonomy browsing, document retrieval, and archiving -- with the same four authentication modes and the same keyboard/group editing infrastructure, adapted for the constraints a web application actually imposes.

`net48`, legacy-style ASP.NET Web Application project. MVC 5 has no official SDK-style project support, so this must stay in the classic format unlike the rest of this solution.

## Key Infrastructure

### SessionConnectionManager

The web equivalent of `ConnectionViewModel`. Because HTTP is stateless, there's no long-lived object to hold a connected `Application` between requests. The solution is `Session` (`InProc` mode) -- the only built-in ASP.NET session mode that can hold a **non-serializable object reference**. `StateServer`/`SQLServer` modes both require session content to be serializable, and the Unity API's own connection objects were never designed for that.

Real tradeoffs of `InProc`: the connection doesn't survive an app pool recycle, and this ties the app to a single server without further work. The documented alternative (not implemented in this first pass) would be reconnecting by Session ID on every request instead of holding the `Application` object itself -- `SessionManagement.Connect(string sessionId)`, the same capability the WPF version's own "Reconnect to Session ID" button exercises.

### SessionLog

The web equivalent of `LogViewModel`. The shared output log held per-session (not as a bound `ObservableCollection` like in WPF), still dual-logging to Serilog's file sinks for persistence past a session.

## What's Genuinely Different From the WPF Version

### Closed Browser Tab Sends Nothing

WPF's `MainWindow.Closing` fires reliably. HTTP gives a web server no signal when a tab closes. The fallback is `Global.asax`'s `Session_End`, which fires only once the session's inactivity timeout elapses (60 minutes in `Web.config`), and only under `InProc` mode.

`SessionConnectionManager.DisconnectOrphanedSession(HttpSessionState)` handles this, taking the session explicitly rather than reading `HttpContext.Current` -- a well-known ASP.NET gotcha: `HttpContext.Current` is unreliable specifically inside `Session_End`.

The Close button in the sidebar is the deliberate version: it disconnects via a real POST, then attempts `window.close()`. Browsers only allow a script to close a tab it opened itself, so the auto-close is not guaranteed. The disconnect always happens; "you may now close this tab" covers the blocked case.

### File Uploads Via Streams, Not Paths

WPF's `NewDocumentRequest.Files` takes local file paths from a file dialog. A web request receives `HttpPostedFileBase` uploads (streams). `ArchivingController.SaveUploadedFiles` writes each upload to a temp directory first; `CleanUpTempFiles` removes them afterward in a `finally` block regardless of success or failure.

### Dynamic Keyword Editor: Form Field Naming Convention, Not Model Binding

The Add/Remove Instance/Value UI's shape (how many instances, how many values) is only known at submit time, generated by client-side JS cloning `<template>` elements. Submitted fields use a naming convention: `kw_group_{groupId}_{instanceKey}_{fieldId}` and `kw_standalone_{keywordId}_{valueKey}`. `ArchivingController.ParseKeywordsFromForm` reconstructs the `KeywordGroup`/`KeywordInfo` lists the library expects by parsing `Request.Form`'s keys directly. Existing values get stable `existingN` keys; JS-added rows get `newN` keys (counter starting well past any realistic existing count) so there's never a collision.

### Search Mode Must Be Persisted, Not Just Toggled Client-Side

Mode switching (Document Type(s)/Custom Query/Document ID) is client-side JS. But after a `Search` POST-then-redirect, JS re-initializes fresh and defaults back to the first tab. Fixed via `RetrievalPageModel.LastSearchMode`, set from the `mode` form field in `Search()`, used by the view to restore the correct active tab after redirect.

### Settings Is Process-Wide, Not Per-Session

`SessionManagement.ServiceLocation`/`IdpSettings` are static, process-wide properties -- not per-session state. Settings changes here affect every user simultaneously. Confirmed intentional for this internal admin tool.

## Lessons Learned the Hard Way

### Serilog Configuration: Abandoned Microsoft.Extensions.Configuration

The first attempt mirrored the WPF version: `Serilog.Settings.Configuration` + `Microsoft.Extensions.Configuration` reading `serilog.json`. This triggered a cascading series of `FileLoadException`s through a deep transitive dependency chain that `AutoGenerateBindingRedirects` failed to resolve reliably for a legacy Web Application project.

The fix: `Global.asax.cs` now parses `serilog.json` directly with `Newtonsoft.Json` (already a dependency, far shallower footprint) and builds `LoggerConfiguration` programmatically from the parsed values. Settings are still fully externally configurable with no recompile needed -- only the loading mechanism changed.

`Web.config` carries a few hand-written `<bindingRedirect>` entries (`Serilog`, `System.Memory`) as safety nets from this saga. If a similar `FileLoadException` appears for a different assembly, get the actual assembly version on disk before adding a redirect:

```powershell
[System.Reflection.AssemblyName]::GetAssemblyName("path\to\the.dll").Version
```

Don't guess from the error message's "requested version" -- that's what's being asked for, not what's present.

### The Razor Nesting Rule

`@if`/`@foreach`/`@using` need the `@` prefix only when transitioning from markup into code, but "currently in markup" is tracked across the **whole** open-tag nesting, not reset per `{ }` block. If a `<div>` that's still open wraps a control structure, the `@` is needed; if everything before it in the open-tag chain is already closed, it isn't.

This caused repeated confusion specifically when restructuring a view's layout (wrapping content in a new outer `<div>`) -- the correct prefix for nested control structures can flip in either direction depending on what's now open around them.

### `Html.Partial` With a `null` Model

Passing `null` as a partial's model doesn't render the partial with a null model -- it falls back to the calling page's own `ViewData.Model`. If the partial's `@model` type doesn't match the parent's, this throws `InvalidOperationException`. Fix: never let a property passed to `Html.Partial` actually be `null`. `RetrievalPageModel.Detail` and `ArchivingPageModel.NewEditorSchema`/`ExistingEditorSchema` all default to a real, empty instance.

### Boolean HTML Attributes Are Presence-Based

`disabled="@(someBool)"` renders as `disabled="False"` when false -- and a browser treats that as present (HTML boolean attributes care whether the attribute exists, not its value string). The fix throughout: `@(condition ? "checked" : "")` as a bare token in the tag, which Razor renders as the attribute name alone when non-empty, or omits entirely when empty.

### CSS Load Order

Loading Bootstrap's CDN stylesheet after `site.css` meant Bootstrap's default element-level rules overrode lower-specificity custom rules. Fixed by loading `site.css` last in `_Layout.cshtml`'s `<head>`.

### Sidebar Height

`.th-shell`'s `min-height: 100vh` is a floor, not a ceiling -- sidebar content exceeding viewport height would expand the whole shell. Fixed to `height: 100vh` with `overflow-y: auto` on `.th-sidebar` so its content scrolls internally, matching `.th-output`'s existing pattern.

## Relationship to Unity.TestHarness (WPF)

The Unity API usage is identical. Where behavior differs, it's because of a genuine web-platform constraint, not a deliberate feature gap:

| WPF | Web |
|---|---|
| Long-lived `Application` field on `ConnectionViewModel` | `Application` held in `InProc` Session |
| `MainWindow.Closing` disconnects reliably | `Session_End` disconnects after inactivity timeout |
| File dialog returns local paths | `HttpPostedFileBase` streams written to temp files |
| `ObservableCollection<LogEntry>` in `LogViewModel` | Per-session `SessionLog` |
| Strongly-typed `KeywordGroupEditor`/`StandaloneKeywordEditor` VMs | Form field naming convention + `ParseKeywordsFromForm` |

## Takeaways

- `InProc` session is not just the default -- it's required to hold a non-serializable `Application` object reference.
- `Session_End` is the delayed safety net for orphaned connections. The Close button is the deliberate one.
- `HttpContext.Current` is unreliable inside `Session_End`. Pass the session explicitly.
- File uploads require a temp-write/cleanup cycle when the underlying library expects file paths.
- Dynamic keyword editing uses a form field naming convention, not model binding, because the shape isn't known until submit.
- `Html.Partial` with a `null` model uses the parent's model. Always default to an empty instance, not null.
- HTML boolean attributes are presence-based. Use a bare conditional token, not `attribute="false"`.
- Get actual assembly versions from disk before writing binding redirects. The error message's "requested version" is not the file version.
