# Samples.WinForms

## What This Is

A Windows Forms desktop application -- the older, simpler sibling of `Samples.Wpf`. Event handlers manipulate controls directly and imperatively, no data binding, no ViewModel, no command objects. Same ZIP code lookup as every other Samples project, backed by EF6 Database-First.

Targets `net48`. WinForms was ported to modern .NET alongside WPF, so a `net10.0` sibling could be added if a meaningfully illustrative difference emerges -- not added by default.

---

## When to Use WinForms

For simple, forms-over-data Windows-only desktop applications where UI needs are straightforward and development speed matters more than visual flexibility or testability. Once UI needs grow more demanding (rich styling, complex layouts, genuine unit testability of UI logic), WPF is the better fit.

---

## How WinForms Works

The UI is C# code. `MainForm.Designer.cs` builds every control with `new Label()`, `Controls.Add(...)`, and property assignments -- generated by the Visual Studio Forms Designer, but readable as plain code. Event handlers live in `MainForm.cs`:

```csharp
private void BtnSearch_Click(object sender, EventArgs e)
{
    string zipCode = txtZipCode.Text;
    using var db = new ExternalDataEntities();
    var results = db.ZipCodes.Where(z => z.ZipCode == zipCode).ToList();
    gridResults.DataSource = results;
}
```

`txtZipCode.Text` is read directly. `gridResults.DataSource = results` populates the grid. No binding, no ViewModel, no command -- the event handler does everything.

Compare this directly against `Samples.Wpf`'s `SearchCommand` in `MainViewModel.cs`, which achieves the same result with no code-behind at all.

## Creating a WinForms Project

### Visual Studio

**File > New > Project**, search "Windows Forms App", choose the one matching your target framework (`.NET Framework` for `net48`, plain "Windows Forms App" for modern .NET), click Next, name it, click Create.

The Forms Designer opens automatically. Drag controls from the Toolbox onto the form. Double-click a button to generate its `Click` event handler stub in the code-behind. The Designer writes all control creation and property code into `Form1.Designer.cs` automatically.

To add EF6 Database-First: right-click the project > **Add > New Item > ADO.NET Entity Data Model**, connect to your SQL Server database, select the `ZipCodes` table, click Finish.

### VS Code

```powershell
dotnet new winforms -n MyWinFormsApp -f net10.0-windows
```

VS Code has no Forms Designer. Controls must be created in code manually in `Form1.Designer.cs`, or created in Visual Studio and edited in VS Code afterward. For any project with a non-trivial UI, Visual Studio's Designer is strongly preferred.

## Running This Project

1. Point `App.config`'s `ExternalDataEntities` connection string at a SQL Server instance.
2. Press F5.
3. Enter a ZIP code and click Search.

---

## Pros and Cons

**Pros:** Very fast to build simple UIs with Visual Studio's drag-and-drop Designer. Low learning curve for event-driven developers. Mature, stable platform.

**Cons:** UI logic is untestable -- `BtnSearch_Click` reads controls directly, no way to unit test without a real form. Imperative, manual control manipulation doesn't scale to complex UIs. Windows-only. No MVVM or DI story.
