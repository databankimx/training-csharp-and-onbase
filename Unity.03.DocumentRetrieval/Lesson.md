# Unity.03.DocumentRetrieval

## What This Is

Document retrieval: building and executing queries, returning hit-list metadata, fetching file content, generating DocPop and UnityPop links, and extension methods for reading keyword data directly off a `Document` object.

---

## What's in This Project

| File | What it does |
|---|---|
| `DocumentRetrieval.cs` | Query building, hit-list retrieval, file fetch, DocPop/UnityPop link generation |
| `Metadata.cs` | Builds keyword objects (`Keyword`, `EditableKeywordRecord`, `QueryKeywordRecord`) from plain data |
| `DocumentExtensions.cs` | Extension methods on `Document` for reading keyword values |
| `Models/Objects/` | DTOs: `RetrievalRequest`, `DocumentInfo`, `DocumentFile`, `DocumentLink`, `KeywordGroup`, `KeywordInfo`, `RevisionInfo`, `RenditionInfo`, `DateRange`, `DocumentData` |

## RetrievalRequest: What a Query Is

`RetrievalRequest` is the DTO that drives `MakeDocumentQuery()`. A minimal request needs only a document type:

```csharp
var request = new RetrievalRequest
{
    DocumentType = "CON - Primary Document"
};
```

Multiple document types in one query (added as `Unity.TestHarness` needed it):

```csharp
var request = new RetrievalRequest
{
    DocumentTypes = new List<string> { "CON - Primary Document", "CON - Amendment" }
};
```

`DocumentTypes` (plural) takes precedence over `DocumentType` (singular) when both are populated. `DocumentType` (singular) is kept for backward compatibility.

Custom query instead of a document type:

```csharp
var request = new RetrievalRequest
{
    CustomQuery = "Active Contracts"
};
```

With keyword filters:

```csharp
var request = new RetrievalRequest
{
    DocumentType = "CON - Primary Document",
    Keywords = new List<KeywordInfo>
    {
        new KeywordInfo { Name = "Vendor Name", Value = "Acme Corp" }
    },
    DateRange = new DateRange { From = DateTime.Today.AddDays(-30), To = DateTime.Today }
};
```

## The Two Retrieval Methods

`GetDocumentInfo` executes the query and returns metadata (no file content):

```csharp
List<DocumentInfo> results = retrieval.GetDocumentInfo(request, app);
// DocumentInfo: DocumentId, DocumentType, Keywords, Revisions, Renditions, etc.
```

`GetDocumentLinks` executes the same query but returns DocPop/UnityPop links instead:

```csharp
List<DocumentLink> links = retrieval.GetDocumentLinks(request, app);
// DocumentLink: DocumentPopLink, UnityPopLink
```

Both use the same `MakeDocumentQuery()` internally -- the query machinery is identical, only what's done with the results differs.

## Document File Retrieval

```csharp
// By document (uses DefaultRenditionOfLatestRevision)
DocumentFile file = retrieval.GetDocumentFile(doc, app);

// By specific rendition (added for Unity.TestHarness's revision/rendition browser)
DocumentFile file = retrieval.GetDocumentFile(rendition, app);

// Prefer PDF when available
DocumentFile file = retrieval.GetDocumentFile(doc, app, preferPdf: true);
```

`DocumentFile.Content` is a `byte[]`. `DocumentFile.Base64Content` computes from it:

```csharp
public string Base64Content => Content == null ? null : Convert.ToBase64String(Content);
```

This is a computed property, not a settable field alongside `Content`. If both were independently settable, they could easily disagree with each other -- the computed approach means there's only ever one source of truth.

The `preferPdf` flag routes through the Unity API's PDF provider (`retrieval.PDF.GetDocument(rendition)`) when the file type supports it. Supported types come from `Unity.00`'s `FileFormat` enum: `Text`, `Image`, `Pcl`, `Word`, `Excel`, `Pdf`. Unsupported types silently fall through to native retrieval rather than failing -- `preferPdf` is a preference, not a requirement.

## DocPop and UnityPop Links

DocPop links open documents in a browser using OnBase's web viewer. UnityPop links open them in the OnBase Unity Client (desktop). Both are generated by `CreateDocPopLink`:

```csharp
DocumentLink link = retrieval.GetDocumentLink(docId, app);
// link.DocumentPopLink  -- browser viewer URL
// link.UnityPopLink     -- desktop client URL
```

DocPop links include an optional `chksum` parameter when `DocPopSettings.DocPopChecksumSeed` is configured, allowing the receiving page to verify the link wasn't tampered with. The checksum calculation (`ChecksumCreator`) comes from `Hyland.Applications.Web.Security`, which is bundled inside the `Hyland.Unity` NuGet package -- no separate reference needed.

One bug fixed here: the checksum was previously calculated unconditionally even when `DocPopChecksumSeed` was blank, causing every `GetDocumentLink` call to throw in environments without a configured seed. The fix skips the `ChecksumCreator` call entirely when the seed is blank, not just the step that appends `&chksum=...` to the URL.

## GetKeywordColumns and MultiInstance Groups

`MakeDocumentQuery` calls `GetKeywordColumns` to add display columns to the `DocumentQuery`. MultiInstance keyword groups are deliberately excluded:

```csharp
if (groupType.RecordType == RecordType.MultiInstance) continue;
```

Adding a MultiInstance keyword group's keyword types as display columns causes OnBase to return one result row **per instance** of that group on a document, not one row per document. A document with two instances of a multi-instance group appears twice in the results as if it were two different documents -- same ID, same data, two rows. Excluding MultiInstance groups prevents this.

This only affects hit-list search display. Once a document is selected, `GetDocumentInfo(Document)` reads the full, real multi-instance keyword data directly from `doc.KeywordRecords`.

## DocumentExtensions: Reading Keywords Off a Document

Extension methods on `Document` for reading keyword values without repeating the `KeywordRecordTypes` traversal:

```csharp
// Get a single keyword value
string vendorName = doc.GetKeywordValue("Vendor Name");

// Get all values for a multi-value keyword
List<string> amounts = doc.GetKeywordValues("Invoice Amount");

// Get keyword values for a specific group instance
string value = doc.GetKeywordGroupValue("Contact Info", "Phone Number", instanceIndex: 0);
```

These are thin helpers over `doc.KeywordRecords` traversal. The same data is accessible directly through the Unity API's `Document.KeywordRecords` collection.

The reference was dropped as an unnecessary dependency -- worth noting as a general habit: a `ProjectReference` not backed by an actual `using` anywhere is dead weight.

## Takeaways

- `RetrievalRequest.DocumentTypes` (plural) enables multi-document-type queries. `DocumentType` (singular) is kept for backward compatibility and ignored when `DocumentTypes` is populated.
- `GetDocumentInfo` returns metadata; `GetDocumentLinks` returns DocPop/UnityPop URLs. Both use the same `MakeDocumentQuery` underneath.
- `DocumentFile.Base64Content` is computed from `Content`, never stored separately. One source of truth.
- `preferPdf` is a preference backed by a known-supported file type list, not a guarantee. Unsupported types fall through silently.
- MultiInstance keyword groups are excluded from hit-list display columns to prevent duplicate result rows. They're still readable per-document via `doc.KeywordRecords`.
- DocPop checksum calculation is skipped entirely when `DocPopChecksumSeed` is blank -- not just the URL parameter, the `ChecksumCreator` call itself.
- `Hyland.Applications.Web.Security` is bundled inside the `Hyland.Unity` NuGet package. No separate reference is needed.
