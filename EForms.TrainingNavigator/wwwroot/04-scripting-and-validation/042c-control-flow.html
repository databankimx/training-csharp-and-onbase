if / else if / else

Runs a block of code only when a condition is true. Try different amounts to see which branch of the chain below actually runs: 

if (amount <= 0) {
    result = "Amount must be greater than zero.";
} else if (amount < 500) {
    result = "No approval needed - amount is under $500.";
} else if (amount < 5000) {
    result = "Requires manager approval ($500-$4,999).";
} else {
    result = "Requires director approval ($5,000+).";
}

Each condition is checked in order, top to bottom. The moment one evaluates to true, that branch runs and every remaining else if/else is skipped entirely - even if a later condition would also have been true.

switch

Compares one value against several possible exact matches - often cleaner than a long if/else if chain when every branch is just checking the same variable. Try a few department codes (try AP, HR, Benefits, or anything else): 

switch (dept) {
    case "AP":
        result = "Routes to Accounts Payable.";
        break;
    case "AR":
        result = "Routes to Accounts Receivable.";
        break;
    case "HR":
    case "Benefits":
        result = "Routes to Human Resources.";
        break;
    default:
        result = "No matching department - routes to General Queue.";
        break;
}

A few things worth knowing about switch:

  • switch compares using === (strict equality) - no type coercion, unlike some other languages you may have used.
  • Don't forget break. Without it, execution "falls through" into the next case below, running that code too, whether you meant to or not. This is a common source of bugs.
  • Falling through is occasionally done on purpose - stacking multiple case labels with no code between them (like "HR" and "Benefits" above) lets several values share the same result.
  • default runs when nothing else matched. It's optional, but usually worth including so an unexpected value doesn't just silently do nothing.
