The Basics

jQuery selectors work like CSS selectors - the same syntax you already know from styling a page:

$("#myField")
Selects The element with that id
Vanilla JS document.getElementById("myField")
$(".myClass")
Selects Every element with that CSS class
Vanilla JS document.getElementsByClassName("myClass")
$("input")
Selects Every element with that tag
Vanilla JS document.getElementsByTagName("input")
$("input[name='x']")
Selects Every <input> with that attribute value
Vanilla JS document.querySelectorAll("input[name='x']")

The practical advantage is consistency: one selector syntax covers id, class, tag, and attribute matching, rather than a different vanilla JS method for each.

A Selector Always Returns a Collection

Even $("#myField"), matching a single unique id, technically returns a jQuery collection - it just happens to contain one element. This matters most with name or class selectors, which commonly match more than one element (radio buttons and checkboxes sharing a name, for example). Use .first() to take just the first match, or .each() (covered in the Traversal and Manipulation lesson) to work with every match.

Try each selector type below against the same field to see this in action: 

switch (findType) {
    case "id":
        el = $("#kwDescription");
        break;
    case "name":
        el = $("input[name='OBKey__1_1']").first();
        break;
    case "tag":
        el = $("input").first();
        break;
    case "class":
        el = $(".keyword");
        break;
}

In practice, selecting by id is by far the most common approach - it's unambiguous, fast, and exactly why every field throughout this training set has one, even on fields where the id isn't otherwise required for anything else.
