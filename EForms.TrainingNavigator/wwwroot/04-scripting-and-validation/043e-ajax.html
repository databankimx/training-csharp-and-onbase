AJAX (the name is historical - originally "Asynchronous JavaScript And XML," though a modern AJAX call almost always sends and receives JSON instead) lets a script call a web service from the browser, without reloading the page or navigating anywhere. This is how a form looks up data from OnBase, or from any other external service, while the user is still filling it out.

The demo below calls a real, working location-lookup service that connects to the ExternalData SQL Server database. The endpoint is hosted in this same application.

Administrator Note: The database connection is configured at deployment time via environment variables or configuration management. Set the ConnectionStrings__DefaultConnection environment variable to your SQL Server connection string:

Server=your-server;Database=ExternalData;User Id=username;Password=password;TrustServerCertificate=true

The Code Behind It

$.ajax({
    url: wsUrl,
    type: "POST",
    contentType: "application/json",
    crossDomain: true,
    xhrFields: {
        withCredentials: true
    },
    data: JSON.stringify({ zipCode: zipCode, requestId: requestId }),
    success: function (result) {
        // runs once the service responds successfully
    },
    error: function (jqXHR, textStatus, errorThrown) {
        // runs if the request fails instead
    },
});

A few things worth understanding about this call:

  • The request body is a JSON string, not a plain object. JSON.stringify() converts the { zipCode, requestId } object into the actual text sent to the server - contentType: "application/json" tells the server how to interpret it.
  • Property names matter. The server expects properties named zipCode and requestId (camelCase). If you send ZipCode or RequestId instead, the backend won't recognize them correctly.
  • xhrFields: { withCredentials: true } tells jQuery to send authentication cookies with this request, which is required since the endpoint enforces authentication.
  • Two separate callbacks handle the two possible outcomes - success if the service responds normally, error if the request fails (the server is unreachable, returns an error status, or similar).

AJAX Is Asynchronous

The "A" in AJAX is the important part: the call doesn't pause the script and wait for a response. $.ajax() sends the request and returns immediately - the code right after it keeps running before any response has come back. The success/error callbacks run later, whenever the response actually arrives.

Why this matters for error handling: a plain try/catch around an AJAX call won't catch a failure from the service itself - by the time the response comes back (success or failure), the try block has already finished running. This is exactly why AJAX calls need their own dedicated error callback, rather than relying on the same try/catch pattern used everywhere else in this training set.
