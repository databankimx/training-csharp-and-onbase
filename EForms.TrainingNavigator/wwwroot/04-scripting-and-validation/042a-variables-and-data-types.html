OnBase note: most OnBase installations only support var. Older forms render using Internet Explorer 9, which predates let/const entirely (both are ES6 features from 2015) - and even on a current, Chromium-based installation, you can't always be sure which engine your form will actually render on. Unless you know for certain your environment is on the modern engine, declare every variable with var.

Declaring a Variable

A variable is a named container for a value you want to use later. In OnBase work, you'll almost always use var: 

var kwDescription = "TEST DATA";

let and const exist in modern JavaScript and are worth knowing about even if you rarely use them here:

  • let - like var, but block-scoped (confined to the nearest { }, such as an if or a loop) rather than function-scoped
  • const - like let, but the variable can't be reassigned after it's first set

var is function-scoped: a variable declared with var anywhere inside a function (even inside an if block) is visible throughout that whole function, not just within the block it was declared in. This is one of var's more surprising quirks compared to let/const, and worth knowing about even though it rarely causes real problems in practice.

A Few Notes on the Types Above

  • There's only one numeric type, number - no separate int/float/decimal like you'd find in C#. 1250.5 and 10 are both just number.
  • bigint is a newer type for integers too large for number to represent precisely - written with an n suffix, like 9007199254740993n. You're unlikely to need it in typical form-scripting work.
  • null and undefined are both "no value," but mean different things: undefined is what a variable has before it's ever assigned anything; null is an explicit, intentional "no value" that you assign yourself.
  • Notice that typeof null reports "object", not "null" - this is a decades-old bug in the language itself that can never be fixed without breaking the web, so it's just something to know rather than something that will ever change.
