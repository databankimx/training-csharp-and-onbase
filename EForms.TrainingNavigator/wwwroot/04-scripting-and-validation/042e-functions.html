Function Declarations and Expressions

There are two common ways to define a function that do the same thing:

// Declaration
function calculateTax(amount, rate) {
    return amount * rate;
}

// Expression - the same thing, assigned to a variable instead
var calculateTaxExpr = function (amount, rate) {
    return amount * rate;
};

A named function declaration is available throughout the whole script (even before the line it's written on, due to "hoisting"), while a function expression only exists from the line it's assigned onward, like any other variable. In practice, either works fine for most form-scripting - declarations are usually the more readable default.

Arrow Functions

A more compact syntax, especially handy for short, one-off functions:

var calculateTaxArrow = (amount, rate) => amount * rate;

Arrow functions have one behavioral difference worth knowing beyond the shorter syntax: they don't have their own this - they use whatever this means in the surrounding code instead. This rarely matters for a short calculation like the one above, but it does matter for the constructor pattern covered later on this page, which is why that example uses a regular function, not an arrow.

Parameters, Defaults, and Return Values

A parameter can have a default value, used only when the caller leaves that argument out entirely: 

function greetVendor(name, greeting = "Hello") {
    return greeting + ", " + name + "!";
}

A function that doesn't explicitly return anything returns undefined automatically - useful to remember when a function seems to silently "not work," since a missing return is a common cause.

The Old-Style "Constructor Function" Pattern

Before the class keyword existed (added in ES6, 2015), a plain function was used to create class-like objects. You'll see this pattern throughout existing OnBase forms, and it still works everywhere - understanding it matters more than the newer class syntax for this reason: 

function Vendor(name, id) {
    this.name = name;
    this.id = id;
    this.describe = function () {
        return this.name + " (Vendor ID: " + this.id + ")";
    };
}

// "new" creates a new object; "this" inside the function refers to it
var vendor = new Vendor("Acme Supply", "V-1042");

Calling a function with new in front of it creates a brand-new, empty object, then runs the function with this pointing at that new object. Anything you assign to this inside the function - properties, or even entire functions, as with describe above - becomes part of the resulting object. Call new Vendor(...) again with different arguments and you get a completely independent object, with its own separate name and id.

OnBase note: the modern class keyword works fine on a current, Chromium-based OnBase installation, but not on an older one still rendering forms with Internet Explorer 9 - the same compatibility issue covered for let/const earlier in this chapter. The constructor-function pattern above works everywhere, on every OnBase version, which is why it's still the safer default to actually write, even though class is worth recognizing when you come across it.
