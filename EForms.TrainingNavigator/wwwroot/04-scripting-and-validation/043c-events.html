`window.onload` vs. `$(document).ready()`

Both run a function once the page is ready, but "ready" means something different for each - and the gap between them is exactly why jQuery's version is almost always the better choice for form scripting:

Fires when...
$(document).ready()The HTML structure (the DOM) has been fully parsed - elements exist and can be found/manipulated
window.onloadEverything has finished loading, including every image, stylesheet, and iframe on the page

$(document).ready() fires first, or at the same time - never later. On a page with large images or slow embedded content, the gap can be substantial; on this simple page, both fire almost immediately, but the actual order is still real and measurable:

In practice: if all you need is to find elements and bind event handlers - which is most form scripting - use $(document).ready(). Reach for window.onload only when you specifically need to know that every image or embedded resource has actually finished loading.

Why this training set uses both: the vanilla JavaScript lessons earlier in this chapter use window.onload, since jQuery hadn't been introduced yet. Every jQuery lesson from here forward uses $(document).ready() instead - the more idiomatic choice once jQuery is available, for the reason explained above.

Binding Events: `.on()` and Shorthand Methods

.on() is the general-purpose way to bind any event to an element:

$("#btnOnDemo").on("click", function () {
    // runs when the button is clicked
});

Shorthand methods exist for the most common events - .click(fn) is equivalent to .on("click", fn), just shorter to type. Both work identically; .on() has the advantage of handling every event through one consistent method, including events with no dedicated shorthand.
