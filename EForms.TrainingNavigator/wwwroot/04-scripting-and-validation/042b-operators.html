&& is true only when both sides are true. || is true when either side is true. ! flips a single value.

Watch out for: & and | (a single character) look like typos of && and ||, but they're a completely different pair of operators - bitwise AND/OR, not logical AND/OR (see below). They produce a number, not a boolean, and won't throw an error if you use one by mistake - the code just quietly does something entirely different than intended. Double-check you have the right number of characters when typing &&/||.

Bitwise Operators

These operate on the actual binary representation of a number, one bit at a time, rather than on the number as a whole - a different job entirely from the logical operators above, despite the similar-looking symbols. They're rarely needed for typical form-scripting work, but worth recognizing if you come across them:

OperatorMeaningExample
&Bitwise AND5 & 3 →
|Bitwise OR5 | 3 →
^Bitwise XOR5 ^ 3 →
~Bitwise NOT~5 →
<<Left shift5 << 1 →
>>Right shift5 >> 1 →

Notice that every result above is a number, not true/false - concrete proof of why mixing these up with the logical operators causes silent, confusing bugs rather than an obvious error.

Operator Precedence

When an expression uses more than one operator, JavaScript doesn't just evaluate left to right - some operators bind more tightly than others, the same way multiplication happens before addition in normal math: 

2 + 3 * 4

This evaluates to , not 20 - * is evaluated before +. Parentheses always override precedence, the same way they do in math:

(2 + 3) * 4

This evaluates to .

The same idea applies to logical operators, and it's a common source of real bugs: && binds tighter than ||, so it's evaluated first even with no parentheses at all: 

true || false && false

This is evaluated as true || (false && false), giving - not (true || false) && false, which would give false instead. When combining && and || in the same expression, add parentheses explicitly rather than relying on precedence rules being obvious to the next person reading the code (including a future you).
