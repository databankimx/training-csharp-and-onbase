The Mistake

Touching the Live DOM on Every Iteration

Every time you touch the live DOM - appending a node, changing text - the browser has to consider whether it needs to recalculate layout. That's a real, measurable cost when it happens thousands of times in a tight loop: 

var list = document.getElementById("myList");
for (var i = 0; i < 2000; i++) {
    var li = document.createElement("li");
    li.textContent = "Item " + i;
    list.appendChild(li);   // DOM touched 2,000 times
}
    The Fix

    Build Off-DOM First, Attach Once

    A DocumentFragment is a lightweight container that isn't part of the rendered page at all - building the new structure there first, then attaching it to the real document in one step, avoids nearly all of that repeated layout cost: 

    var list = document.getElementById("myList");
var fragment = document.createDocumentFragment();
for (var i = 0; i < 2000; i++) {
    var li = document.createElement("li");
    li.textContent = "Item " + i;
    fragment.appendChild(li);
}
list.appendChild(fragment);   // DOM touched once

      Run both versions a few times and compare the reported milliseconds directly - the fragment version should consistently come out well ahead, especially as the item count grows. Timing a single loop like this is a much more reliable comparison than the memory-leak demo earlier in this chapter, since it doesn't depend on unpredictable garbage collection timing - just how long the loop itself actually takes to run.
