The Mistake

A Prototype Property Is Shared, Not Copied

JavaScript uses prototypal, not classical, inheritance - a property assigned directly on a constructor's prototype is a single, shared value, not a per-instance copy the way a field in a classical language's class would be: 

function Animal() {}
Animal.prototype.sounds = [];   // ONE array, shared by every instance

var dog = new Animal();
var cat = new Animal();
dog.sounds.push("Woof");
console.log(cat.sounds);   // ["Woof"] - unexpected!

dog and cat are two separate instances, but they both inherit the exact same sounds array from Animal.prototype - there's only ever one array, and every instance points at it. Pushing to dog.sounds is visible through cat.sounds too, since they're not two arrays at all, just one array seen from two places.

The Fix

Assign Instance State Inside the Constructor

Give each instance its own independent copy by assigning it inside the constructor itself:

function AnimalFixed() {
    this.sounds = [];   // a NEW array, created fresh for every instance
}

var dog2 = new AnimalFixed();
var cat2 = new AnimalFixed();
dog2.sounds.push("Woof");
console.log(cat2.sounds);   // [] - as expected

Because this.sounds = [] runs fresh every time new AnimalFixed() is called, each instance gets its own independent array from the start. Pushing to one has no effect on the other. As a rule of thumb: put shared behavior (methods) on the prototype, and put per-instance state (anything that should vary independently between objects) inside the constructor, assigned to this.
