The Mistake

A Method Reference, Detached From Its Object

Closely related to the "Losing Track of "this"" lesson earlier in this chapter, but worth its own lesson: pulling a method off an object into a standalone variable detaches it from that object entirely, not just when it's assigned as an event handler: 

var user = {
    name: "Alice",
    greet: function () {
        return "Hello, I'm " + this.name;
    }
};

user.greet();                  // "Hello, I'm Alice" - called ON the object, works fine

var greetFn = user.greet;      // just the function itself, no connection to "user"
greetFn();                     // "Hello, I'm " - this.name is now window.name, not "Alice"

greetFn looks like it should behave exactly like user.greet - it's the same function, after all. But once it's assigned to a plain variable, JavaScript has no way of knowing it was ever associated with user at all; calling greetFn() is a completely ordinary function call, with this pointing at the global object instead. In a browser, that global object happens to have its own built-in name property (used for cross-window/cross-frame targeting), which defaults to an empty string rather than being undefined - so the result is a name that's silently blank, not an obvious error. The specific result here depends on that particular built-in property; the general problem - this no longer pointing at user at all - is what actually matters and generalizes to any object, not just this one.

The Fix

Bind It Before Handing It Off

Lock this to user explicitly, before the function is extracted or passed anywhere else:

var boundGreet = user.greet.bind(user);
boundGreet();                  // "Hello, I'm Alice"

boundGreet behaves correctly no matter how it's later called, passed around, or assigned - this is permanently locked to user the moment .bind(user) runs, and nothing can change that afterward.

When this actually comes up: passing a method as a callback - to setTimeout, to an array method like .forEach(), or storing it for later use elsewhere - is functionally the same as extracting it into a variable first. Any time a method is handed off rather than called directly on its object, bind it first unless you're certain this won't be needed inside it.
