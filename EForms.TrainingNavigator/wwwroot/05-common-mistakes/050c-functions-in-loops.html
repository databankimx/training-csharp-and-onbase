The Mistake

Every Closure Shares the Same `var`

Which number does each button below log when clicked, once they're created?

for (var i = 0; i < 3; i++) {
    var btn = document.createElement("button");
    btn.onclick = function () {
        console.log("This button logs: " + i);
    };
    container.appendChild(btn);
}
(click a button above once created)

Create the buttons, then click each one - every single one logs 3, regardless of which button you actually click, and regardless of the fact that only buttons labeled "Button 0" through "Button 2" were ever created. This is a direct consequence of the previous lesson's scoping issue: since var creates only one i for the whole loop, every closure captures that same variable, not the value it happened to hold at the moment the closure was created. By the time any button is actually clicked, the loop has long since finished, and i holds its final value - 3, the value it reached right after the last iteration's increment, one step past the last value the loop body itself actually used.

The Fix

`let` Gives Each Pass Its Own Binding

The same loop, with let in place of var:

for (let j = 0; j < 3; j++) {
    var btn = document.createElement("button");
    btn.onclick = function () {
        console.log("This button logs: " + j);
    };
    container.appendChild(btn);
}
(click a button above once created)

This time, each button correctly logs its own number. let creates a fresh, independent j for every single pass through the loop, so each closure captures its own separate value rather than all sharing one. This is one of the most common reasons to prefer let over var for loop counters in general - not just the scoping quirk from the previous lesson on its own, but this specific, very common downstream consequence of it.
