The Mistake

`var` Outlives the Loop It Was Declared In

For the code below, what would you expect i to be immediately after the loop finishes? 

for (var i = 0; i < 10; i++) {
}
console.log("i after the loop = " + i);

var is scoped to the enclosing function, not the { } block it's declared in. The loop doesn't create a new, private i for itself - it's reusing the exact same variable the rest of the function can see, and that variable keeps whatever value it last held once the loop is done.

The Fix

`let` Is Scoped to the Block

The same loop, with let in place of var:

for (let j = 0; j < 10; j++) {
}
console.log("j after the loop = " + j);   // throws - j doesn't exist out here

let creates a variable confined to the nearest { } - here, the loop itself. Once the loop ends, j simply doesn't exist anymore, which is exactly why referencing it afterward throws a ReferenceError rather than returning a leftover value. Prefer let for loop counters (and variables generally) in any code that doesn't need to support very old browsers or pre-2022 OnBase forms - see the Variables and Data Types lesson for that compatibility caveat.
