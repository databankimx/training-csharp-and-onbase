The Mistake

Handing Off a Method as a Bare Reference

A method called on its object (counter.increment()) has this set correctly. But hand that same function off as a bare reference - exactly what happens when it's assigned directly as an event handler - and this no longer points to the original object at all: 

var detached = counter.increment;
detached();   // "this" inside increment() is no longer "counter"

Called as a plain function like this, this becomes the global object, which has no count property - so this.count++ silently produces NaN rather than throwing an error, which makes this particular mistake easy to miss. Assigned as a real event handler instead - document.getElementById("btn").onclick = someObject.someMethod; - this becomes the button that was clicked instead, which is the version you'll run into most often in real form scripting.

The Fix

Lock `this` with `.bind()`

Function.prototype.bind() returns a new function permanently tied to whatever object you pass it, regardless of how that new function is later called: 

var bound = counter.increment.bind(counter);
bound();   // "this" is "counter", no matter how "bound" is called

This is the standard fix whenever a method genuinely needs to be handed off elsewhere as a callback - document.getElementById("btn").onclick = someObject.someMethod.bind(someObject); keeps working correctly no matter what actually triggers the call.
