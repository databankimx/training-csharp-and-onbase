The Mistake

A Closure Keeps Its Whole Scope Alive

JavaScript is garbage-collected, but a reference held somewhere unexpected can keep an object alive indefinitely. Here, unused is never actually called - but as long as it exists, it keeps priorThing (and the large object it references) reachable, purely because a closure keeps its entire enclosing scope alive for as long as the closure itself is reachable, even variables the closure never actually uses: 

function replaceThingLeaky() {
    var priorThing = leakyThing;
    var unused = function () {
        if (priorThing) console.log("this never runs");
    };
    leakyThing = {
        bigData: new Array(1000000).join("*"),   // a ~1MB string
        unused: unused,   // keeps the closure - and priorThing - reachable
    };
}
The Fix

Don't Capture What You Don't Need

The same function, with the unnecessary closure removed entirely:

function replaceThingFixed() {
    var priorThing = leakyThing;
    // No closure captures priorThing - nothing keeps it reachable once
    // leakyThing is reassigned below.
    leakyThing = {
        bigData: new Array(1000000).join("*"),   // a ~1MB string
    };
}

With nothing keeping priorThing reachable, each old object becomes eligible for garbage collection as soon as leakyThing is reassigned - heap growth should be noticeably lower running this version the same number of times.

A caveat worth being honest about: garbage collection timing is still not fully deterministic even with a settling delay before each measurement - the browser decides when to actually reclaim memory, not your code. Click each "Run 300 Times" button a few times in a row to see a clearer trend rather than judging from a single run, and treat the numbers here as illustrative rather than a precise benchmark.
